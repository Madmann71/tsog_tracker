## 1. Архитектура системы: «Тонкий клиент + Git-хранилище»

Система спроектирована по принципу **Offline-First (приоритет автономной работы)** с централизованным хранением состояния в Git:

```
[Смартфон Android] <───┐
[Смартфон iPhone]  <───┼──> [Приватный GitHub Gist / Репозиторий]
[Компьютер ПК]     <───┘    (Файл tsog_inventory.json: остатки, история, ЗИП)
```

* **Клиент (Frontend):** единый автономный файл `index.html` (HTML5, Tailwind CSS, Lucide Icons, Vanilla JS). Не требует компиляции, установки Node.js или внешних веб-серверов.
* **Локальный кэш:** на каждом устройстве данные дублируются в `localStorage`. Приложение мгновенно открывается в подвалах, боксах мастерской и на удаленных рубежах без подключения к сети.
* **БД в приватном Git:** актуальное состояние хранится в зашифрованном/секретном репозитории GitHub Gist, доступном только владельцу токена.

## 2. Выгрузка приложения на GitHub Pages (Хостинг клиента)

Чтобы не передавать файл `index.html` вручную на каждый телефон, разместите его на бесплатном статическом хостинге **GitHub Pages**.

### Шаг 1. Создание репозитория
1. Войдите в свой аккаунт на [github.com](https://github.com/).
2. Нажмите кнопку **New** (создать новый репозиторий).
3. Укажите имя репозитория, например: `tsog-tracker`.
4. Выберите тип: **Public** (для бесплатного GitHub Pages на стандартном тарифе) или **Private** (если у вас тариф GitHub Pro/Enterprise).
   > *Примечание по безопасности:* В репозитории размещается только программный код оболочки (`index.html`). Ваши реальные приборы, серийные номера и остатки в этот репозиторий **не попадают** — они сохраняются в отдельном приватном Secret Gist.
5. Нажмите **Create repository**.

### Шаг 2. Загрузка файла приложения
1. На странице созданного репозитория нажмите **Add file** → **Upload files**.
2. Перетащите файл `index.html` (из архива проекта).
3. Внизу страницы нажмите зеленую кнопку **Commit changes**.

### Шаг 3. Включение GitHub Pages
1. Перейдите во вкладку **Settings** репозитория (в верхнем меню).
2. В левой колонке выберите раздел **Pages**.
3. В блоке **Build and deployment** под заголовком **Branch** выберите ветку `main` (или `master`) и папку `/ (root)`.
4. Нажмите **Save**.
5. Через 1–2 минуты обновите страницу: вверху появится ссылка вида:
   ```
   https://<ваш-логин>.github.io/tsog-tracker/
   ```
Эту ссылку можно открывать на любых компьютерах и смартфонах сотрудников.

## 3. Установка клиента на смартфоны (Android и iPhone)

Приложение является Progressive Web App (PWA) и устанавливается как нативная программа без магазинов Google Play или App Store.

### Установка на Android (Google Chrome)
1. Откройте полученную ссылку в браузере **Google Chrome**.
2. Нажмите меню браузера (**три вертикальные точки** в правом верхнем углу).
3. Выберите пункт **«Установить приложение»** (или **«Добавить на главный экран»**).
4. Нажмите **«Установить»**.
5. **Результат:** на рабочем столе появится иконка «Мастерская ТСОГ». Приложение запускается в отдельном окне без рамок браузера, задействует встроенную камеру для сканирования QR-бирок и работает офлайн.

### Установка на iPhone / iPad (Apple Safari)
1. Откройте ссылку **строго в браузере Safari** (движок iOS разрешает добавление PWA только через Safari).
2. Нажмите кнопку **«Поделиться»** в нижней панели (квадрат со стрелкой вверх).
3. Прокрутите список действий вниз и нажмите **«На экран «Домой»»** (Add to Home Screen).
4. В верхнем правом углу нажмите **«Добавить»**.
5. **Результат:** на домашнем экране iOS появится ярлык приложения. Программа открывается в полноэкранном режиме, сохраняя все локальные данные в памяти устройства.

## 4. Реализация базы данных в приватном GitHub (Secret Gist)

Для хранения базы данных используется механизм **GitHub Gist REST API**. Он бесплатен, не требует настройки SQL-серверов и обеспечивает прямое шифрование трафика по HTTPS/TLS.

### Шаг 1. Создание персонального токена доступа (Personal Access Token)
1. В правом верхнем углу GitHub нажмите на свой аватар → **Settings**.
2. В самом низу левого меню выберите **Developer Settings**.
3. Перейдите в **Personal access tokens** → **Tokens (classic)**.
4. Нажмите **Generate new token** → **Generate new token (classic)**.
5. В поле **Note** введите назначение: `tsog-db-sync`.
6. Срок действия (**Expiration**): выберите удобный период (например, `No expiration` или `1 year`).
7. В списке полномочий (scopes) отметьте **одну галочку**:
   * `[x] gist` — предоставляет право создавать и обновлять скрытые Gist-файлы.
8. Нажмите внизу зеленую кнопку **Generate token**.
9. **Обязательно скопируйте токен** (начинается на `ghp_...`). GitHub показывает его только один раз.

### Шаг 2. Первичная привязка базы в приложении
1. Запустите приложение на телефоне или ПК.
2. Войдите под ролью мастера с правом записи (по умолчанию: Николай, ПИН `1111`).
3. В правом верхнем углу нажмите кнопку **«Облако»**.
4. Вставьте скопированный токен в поле **«2. Ключ записи (GitHub Token)»**.
5. Нажмите кнопку **«Выгрузить в GitHub (Push)»**.
6. Приложение автоматически отправит структуру базы в GitHub, создаст приватный Gist и заполнит поле **«1. ID облачной базы (Gist ID)»** (32-символьный буквенно-цифровой идентификатор).

### Шаг 3. Подключение устройств остальных сотрудников
* **Для мастеров (с правом перемещений, списаний и правок):**
  На телефоне мастера откройте меню «Облако» → введите **Gist ID** и **GitHub Token**.
* **Для дежурных по заставе / проверяющих (режим «Только просмотр»):**
  Введите **только Gist ID** (поле токена оставьте пустым). У них будет автоматически подтягиваться актуальный остаток, но кнопка отправки правок в облако будет аппаратно заблокирована.

## 5. Логика автоматической синхронизации «на лету»

Вам не требуется каждый раз вручную открывать меню и нажимать кнопки «Загрузить» или «Выгрузить». Приложение управляет обменом данных самостоятельно:

### Автоматическая выгрузка изменений (Auto-Push)
1. Мастер выполняет любое действие: списывает кабель, меняет статус прибора на «В ремонте», переносит блок со Склада в Мастерскую или проводит ТО КИП.
2. Изменение мгновенно записывается в локальную память телефона (`localStorage`).
3. Скрипт синхронизации запускает таймер с задержкой 1.2 секунды (debouncing). Если за это время мастер вносит еще правку, таймер сбрасывается, исключая лишние частые сетевые запросы.
4. Клиент отправляет запрос `PATCH https://api.github.com/gists/<GIST_ID>` с обновленным JSON-пакетом. В шапке приложения статус сменяется на `🟢 GitHub Live`.

### Автоматическая подтяжка изменений (Auto-Pull)
1. **Фоновый опрос:** каждые 15 секунд клиент при наличии интернета опрашивает GitHub. Запрашивается только мета-заголовок `updated_at`. Если файл в облаке не менялся, тяжелый JSON не скачивается (экономия трафика).
2. **Событийный опрос:** проверка инициируется автоматически при:
   * переключении на вкладку приложения (`visibilitychange`);
   * разблокировке экрана смартфона (`window.onfocus`);
   * восстановлении связи после обрыва (`window.ononline`).
3. При обнаружении свежих изменений от другого мастера интерфейс тихо обновляет списки и бейджи остатков без перезагрузки вкладки и без сброса позиции экрана.

### Поведение при отсутствии связи (Офлайн на рубеже / заставе)
* Если мастер работает в экранированном помещении или на участке границы без связи, интерфейс функционирует без ограничений.
* Все операции накапливаются в журнале и сохраняются в кэше.
* Как только устройство подключается к мобильному интернету или Wi-Fi, приложение выдает уведомление *«Интернет подключен: синхронизация...»* и автоматически выгружает сохраненное состояние в облако.

## 6. Структура данных и разграничение прав доступа

База данных хранится в файле `tsog_inventory.json` следующего формата:

```json
{
  "version": 42,
  "updatedAt": "2026-10-18 11:30",
  "updatedBy": "Николай (Ст. мастер)",
  "editorsList": [
    { "name": "Николай (Ст. мастер)", "pin": "1111", "role": "admin" },
    { "name": "Инженер ТСОГ", "pin": "2222", "role": "master" },
    { "name": "Мастер ВОЛС", "pin": "3333", "role": "master" },
    { "name": "Дежурный по заставе", "pin": "0000", "role": "viewer" }
  ],
  "items": [
    {
      "id": "item-1",
      "code": "TSOG-001",
      "room": "sklad",
      "category": "device",
      "name": "Камера IP тепловизионная DS-2TD2617B",
      "serial": "С/Н K8829104",
      "status": "ok",
      "qty": 2,
      "unit": "шт.",
      "minQty": 1,
      "resCurrent": 0,
      "resMax": 0,
      "nextMaint": "2027-04-01",
      "unitOrigin": "Резерв отряда",
      "assignee": "Николай (Ст. мастер)",
      "notes": "Новые в упаковке, проверены на стенде.",
      "usedParts": [],
      "history": [
        { "ts": "2026-10-18 09:00", "text": "Оприходовано на 1. Склад (2 шт.) — Николай" }
      ]
    }
  ],
  "logs": [
    { "ts": "2026-10-18 10:15", "text": "Перемещение: БЛ-4 из «1. Склад» в «2. Мастерская» — Николай" }
  ]
}
```

### Модель безопасности и трехуровневые права доступа
* **1-й уровень — «Только просмотр» (Дежурные по заставе / Проверяющие):**
  - Доступ к контролю остатков на складе, просмотру приборов в ремонте и поиску по QR-бирокам.
  - Любые операции списания, перемещения, редактирования и выгрузки в облако аппаратно заблокированы.
* **2-й уровень — «Мастер / Редактор» (Инженер ТСОГ, Мастер ВОЛС):**
  - Вход по персональному 4-значному ПИН-коду.
  - Полный доступ к операциям учета: приход, списание, перемещение между складом, мастерской, слесаркой и выездами, оформление актов ремонта и синхронизация с сервером/облаком.
  - **Блок управления пользователями и правами скрыт:** мастер не может менять ПИН-коды, добавлять других пользователей или менять права доступа.
* **3-й уровень — «Главный администратор» (Николай):**
  - Вход по персональному ПИН-коду (по умолчанию: ).
  - Полные права на ведение учета + **эксклюзивный доступ к панели «Управление пользователями и правами»**.
  - Возможность в один клик:
    - переключать роль любого сотрудника между «Мастер (Правки)» и «Только просмотр»;
    - менять или сбрасывать ПИН-коды сотрудников;
    - добавлять новых мастеров или дежурных;
    - удалять учетные записи (с защитой от удаления последнего администратора).
* **Централизованная синхронизация прав:** список пользователей, их роли (, , ) и ПИН-коды хранятся внутри JSON-базы. Любое изменение прав главным мастером моментально распространяется на все телефоны и компьютеры через автосинхронизацию.

## 7. Альтернатива: Локальный сервер мастерской (LAN / Wi-Fi без интернета)

Если регламент пограничной службы строго запрещает передачу данных через внешние сети, система переводится в режим автономного локального концентратора:

1. На любом компьютере или ноутбуке мастерской запускается легкий сервер `server.py` (чистый Python 3, встроенные библиотеки, нулевые зависимости):
   * **Windows:** двойной клик по **`start_windows.bat`**.
   * **Linux / Raspberry Pi:** команда `bash start_linux.sh`.
2. Консоль выводит локальный IP-адрес:
   ```
   ======================================================================
     СЕРВЕР МАСТЕРСКОЙ ТСОГ ЗАПУЩЕН И ГОТОВ К РАБОТЕ
   ======================================================================
     1. На этом ПК в браузере:        http://localhost:8080
     2. На смартфонах Android (Wi-Fi): http://192.168.1.105:8080
   ----------------------------------------------------------------------
     * База данных хранится в:        database.json
     * Автосинхронизация активна:     опрос каждые 2.5 сек
   ======================================================================
   ```
3. Смартфоны подключаются к внутренней Wi-Fi точке доступа мастерской (без выхода в город).
4. В браузере смартфона открывается указанный IP (`http://192.168.1.105:8080`).
5. Устройства обмениваются данными напрямую по локальной сети с задержкой менее 0.1 секунды. База записывается в файл `database.json` на диске рабочего компьютера.
